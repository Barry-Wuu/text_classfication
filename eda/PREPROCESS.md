# 数据预处理建议

本文针对 `train_augmented.csv` 提出一套**可执行**的文本预处理建议。所有结论都基于对本数据集的实际扫描，不是通用套话。

先说结论：**这个数据集比想象中干净**，但有两个必须处理的坑——一个是 `U+202E` 方向控制符（真实污染），一个是极易被误删的隐私打码 `*`。标点和繁体的重要性远低于这两项。

---

## 一、扫描结果概览

对全量 30,000 条、427 万字符做字符级统计：

| 字符类型 | 数量 | 占比 |
| --- | ---: | ---: |
| 汉字 | 3,457,027 | 80.89% |
| 标点 | 389,035 | 9.10% |
| ASCII 数字 | 304,591 | 7.13% |
| 空白 | 63,680 | 1.49% |
| ASCII 字母 | 56,838 | 1.33% |
| emoji / 非汉字符号 | 343 | 0.008% |
| 其他 | 2,386 | 0.06% |

数据以汉字为绝对主体，噪声字符占比不高。下面按“危害程度”从高到低排列。

## 二、必须处理：U+202E 方向控制符

### 问题

数据中有 **13 条样本**（占 0.043%）含有 `U+202E`（RIGHT-TO-LEFT OVERRIDE，从右到左覆盖）与 `U+202C`（POP DIRECTIONAL FORMATTING）控制符，各 154 个，且**全部成对出现**。

这类控制符的作用是让其后文本按从右到左显示。原始文本被人为插入了它们，导致**字符顺序在视觉上被打乱**：

```
原：…2026 年 6 月 2 日在京‮线东‬下门店‮买购‬美的 BS50S6W 蒸‮一烤‬体机…
```

“京线东下门店买购”读起来是乱的，正常应为“京东线下门店购买”。

### 为什么必须修

这不是显示问题——**控制符是真实存在于 CSV 字节里的**。模型 tokenizer 会把 `U+202E` 当成一个真实 token 喂进网络，而它附近的字序又是错乱的。等于给模型投喂了 13 条语义错乱 + 含未知字符的样本，是明确的数据污染。

### 修法

把每个 `U+202E … U+202C` 区间内的内容反转回正常顺序，再删掉控制符：

```python
import re

def fix_rlo(text: str) -> str:
    # 将 RLO...PDF 区间内的字符反转（因为原插入时是反着放的）
    text = re.sub(r"\u202e(.*?)\u202c", lambda m: m.group(1)[::-1], text)
    # 清掉落单/残留的方向控制符
    return text.replace("\u202e", "").replace("\u202c", "")
```

实测修复效果：

```
原：在京‮线东‬下门店‮买购‬美的
修：在京东线下门店购买美的
```

**注意**：反转的前提是原文本的插入方式为“整段反放 + 两侧加控制符”（本数据集正是如此）。修复后建议人工抽查这 13 条，逐条确认语义通顺再入库。

## 三、千万别删：隐私打码 `*`

### 问题

全数据集含 **32,420 个** `*`，集中在手机号、订单号、身份证等位置：

```
联系电话为 131*******   交易单号：42000********09   货单号：NO.000***）
```

### 为什么不能删

这是**真实的隐私脱敏痕迹**，不是噪声。`131*******` 这个模式本身就携带“这里是一个手机号”的信息，模型可能借此关联到“金融支付”“通讯运营商”等类别。如果按“删除所有非中文非字母数字字符”的通用规则一刀切，会同时抹掉这类有判别力的结构信号。

### 建议

- **保留 `*` 原样**，不删、不替换。
- 若使用 BERT（词表里没有 `*`），它会被切到 `[UNK]`——这也可以接受，但更好的做法是把连续 `*` 统一压缩成一个（`131*******` → `131*`），既保留“此处被脱敏”的信号，又减少 `[UNK]` 数量。

```python
text = re.sub(r"\*{2,}", "*", text)   # 连续星号归一化（可选）
```

## 四、标点处理

### 4.1 半角转全角：可以统一转，但要排除三个符号

半角标点统一转全角是合理的（减少词表碎片），数据中**已是全角为主**（`，` 192,045 次），混入的半角量为：

| 半角标点 | 数量 | 是否转全角 | 理由 |
| --- | ---: | :---: | --- |
| `,` | 671 | ✅ 转 `，` | 纯中文标点用法 |
| `(` `)` | 1,125 | ✅ 转 `（）` | 纯中文标点用法 |
| `"` | 778 | ✅ 转 `”` | 中文引号 |
| `: ` | 2,504 | ✅ 转 `：` | 81% 是时间（`2:55`），中文时间也用全角冒号 |
| `;` | 73 | ✅ 转 `；` | 中文标点 |
| `!` `?` | 142 | ✅ 转 `！？` | 中文标点 |
| `.` | 53,500 | ⚠️ 分步处理 | 见 4.2 |
| `-` | 2,448 | ❌ **不转** | **92% 是范围/型号**（`C13-C15`、`2000-5000元`、`2026-5-18`、`L6EM-i`） |
| `/` | 1,451 | ❌ **不转** | **96% 是单位/并列**（`3V/5V`、`80km/h`、`实操指导/高收益`） |
| `'` | 13 | ❌ **不转** | 全是拼音注音（`dao'hang'lu'xian`） |

**关键**：`-`、`/`、`'` 必须排除。 实测数据表明它们在中文语境里不是标点，而是**数字和字母之间的连接符**：

- 若把 `2000-5000元` 转成 `2000—5000元`、把 `80km/h` 转成 `80km、h`，语义直接被破坏；
- 这类符号恰恰是型号、单位、时间范围等**判别力很强的特征**（还记得 `-` 常出现在 `L6EM-i`、`K70` 这类产品型号里吗），转坏得不偿失。

因此转换表是**白名单式**的——只列确定要转的，其余保持原样：

```python
def to_fullwidth_punct(text: str) -> str:
    table = str.maketrans({
        ",": "，", ":": "：", ";": "；", "!": "！", "?": "？",
        "(": "（", ")": "）", '"': "”",
        # 故意不含 - / ' ：数字化/型号化用途，转了会破坏语义
    })
    return text.translate(table)
```

### 4.2 半角句点 `.`：唯一需要分步处理的

ASCII 句点 53,500 次，**不能简单转换**，因为它混着三类用途：

| 用途 | 例子 | 处理 |
| --- | --- | --- |
| 省略号 | `产品设计缺陷不...` | 连续点 → 单省略号 `…` |
| 列表序号 | `1. 售前销售全程`、`2. 商家宣传每日` | 保留（或按需转 `、`） |
| 真句末 | 少数以句点结尾的句子 | → `。` |

稳妥做法是**分两步**：先把 `\.{2,}` 处理成省略号（这一步必须在半角转全角之前，否则 `.` 先变成 `。` 就识别不出省略号了），再处理剩余的单个 `.`。由于本数据里单个 `.` 绝大多数是列表序号，**建议保留原样**，避免转成 `1。 售前` 这种错误：

```python
text = re.sub(r"\.{2,}", "…", text)   # 第一步：连续点归一为单省略号
text = re.sub(r"…{2,}", "…", text)    # 已有的 … 也压成一个
# 第二步：单个 . 保留（多为列表序号 1. 2. 3.），不转
```

**省略号统一用单字符 `…`**（U+2026），不用双写 `……`。部分原始文本本身就有 `……`，也一并压成单个 `…`，保证全库形态一致。

### 4.3 标点重复

有 **14,517 条样本**含 3 连以上标点，主要是表达情绪的重复（`！！！` 82 次、`？？？` 17 次、`，，，，` 若干）。这类**建议压缩为一个**，因为重复本身不提供额外语义，反而制造罕见 token：

```python
text = re.sub(r"([，。！？；：、…])\1{1,}", r"\1", text)   # 合并连续重复标点
```

**是否保留情绪强度**（`！！！` vs `！`）是一个取舍：若模型需要捕捉“情绪激烈度”，可保留重复；但本任务是**领域分类**，情绪不是判别依据，压缩更干净。

### 4.4 标点该不该整体删除？

**不该**。 本数据集是分类任务，标点承担着**断句和结构**信息（例：“要求退款 66 元，商家拒绝” 与 “要求退款，66 元商家拒绝” 语义不同）。删除所有标点会破坏这种结构。词云环节已经把标点排除在词频统计之外了，那是分析需要；**训练时保留标点**。

## 五、emoji 与非汉字型情绪符号

### 扫描结果

按 Unicode 类别扫描，全数据集“非汉字型符号”约 **343 次**，主要几类：

| 符号 | 数量 | 说明 |
| --- | ---: | --- |
| `U+FFFC` 对象替换符 | 139 | **图片占位符**（原图未导出，只剩占位） |
| `✅` `❌` `✖` `✔` | 约 40 | 打勾/打叉 |
| `→` | 59 | 箭头（常被当分隔符用） |
| `➕` `➗` `✖` | 81 | 数学符号 |
| `℃` `°` | 59 | 温度符号 |
| `●` `★` `◦` | 28 | 装饰符号 |
| `U+FE0F` 变体选择符 | 36 | emoji 修饰符（如 `✖️`、`1️⃣`） |

### 结论：**剔除**，但注意两个细节

这类符号对**领域分类**没有判别价值（不像品牌名、型号那样能提示类别），应当剔除。用一段 Unicode 范围正则覆盖：

```python
_EMOJI_RE = re.compile(
    "[\U0001F000-\U0001FAFF"   # emoji 主体
    "\U0001F1E6-\U0001F1FF"   # 国旗
    "\U00002600-\U000027BF"   # 杂项/装饰符号（☀✅❌✖★♪）
    "\U00002190-\U000021FF"   # 箭头
    "\U00002B00-\U00002BFF"
    "\U0000FE00-\U0000FE0F"   # 变体选择符
    "\U0000200D\U000020E3"    # 零宽连接符、键帽组合
    "\U0000FFFC\U0000FFFD"    # 图片占位、乱码替换符
    "]+")
text = _EMOJI_RE.sub("", text)
```

**细节一 别误删键帽里的数字**。 `1️⃣` 由 `1` + `U+FE0F` + `U+20E3` 组成，剔除时只能删修饰符，`1` 要留下。上面正则只匹配 emoji 段，数字不在范围内，实测 `1️⃣准时送到` → `1准时送到`，数字保留 ✓。

**细节二**：`℃` `→` 这类“有意义的符号”要不要删？ 它们本质也是符号，但对内容有实际含义（温度、流程指向）。本方案把它们一并剔除（用户要求“非汉字型情绪词剔除”），剔除后不补空格，让前后文自然相接。若后续发现 `℃` 的丢失影响“空调/冰箱”相关类别，可单独考虑保留。

## 六、重复语气词

### 扫描结果与收窄

用户示例是“啊啊啊 → 啊”。但实测全数据集中，**真正的语气词重复极少**（`啊啊啊` 这种），仅 10 条。反而扫到一批“看似重复、实为品牌名或拟声词”的：

| 形态 | 数量 | 真实身份 | 能否压缩 |
| --- | ---: | --- | :---: |
| `多多多多` | 8 | **拼多多**（品牌） | ❌ 不能 |
| `充充充` | 12 | 拟声/强调 | ❌ 不能 |
| `咚咚咚` | 10 | 拟声（水流声） | ❌ 不能 |
| `团团团` | 4 | **快团团**（品牌） | ❌ 不能 |
| `滋滋滋滋` | 4 | 拟声（电流声） | ❌ 不能 |
| `啊啊啊` | 1 | 语气词 | ✅ 可以 |

**关键结论**：不能按“任意汉字重复 ≥3 就压缩”处理，否则会把 `拼多多` 压成 `拼多`、`快团团` 压成 `快团`，破坏品牌词——而这些品牌词恰恰是分类的强特征。

因此本方案采用**语气词白名单**，只压缩白名单里的字：

```python
_TONE_WORDS = "啊呀吧呢吗嘛哦噢喔诶唉哎嗨哈嘿呵嘻嗯唔哟咦哇咯啦嘞唷"
text = re.sub(r"([" + _TONE_WORDS + r"])\1{1,}", r"\1", text)   # 啊啊啊→啊
```

实测 `啊啊啊` → `啊`，而 `快团团`、`咚咚咚`、`滋滋滋滋`、`多多多多` **全部原样保留**。

> 取舍说明：白名单外的重复汉字（如 `房房房`、`钱钱钱`）不动。这类本数据里极少，且难以与品牌/拟声区分，宁可不压也不要误伤。

## 七、繁体字

### 扫描结果

用常见繁简差异字探测，全数据集仅命中 **33 个**疑似繁体字（`個` 20、`這` 6、`門` 5、`們` 2），分布极稀疏。

### 结论

**基本可忽略**。33 个字符散落在 30,000 条里，对模型训练无实质影响。若追求极致干净，可用 `opencc` 做一次繁转简兜底：

```python
from opencc import OpenCC
cc = OpenCC("t2s")
text = cc.convert(text)
```

但收益极低，且 `opencc` 会引入额外依赖。**建议**：不做，或列为可选步骤。

## 八、空白与不可见字符

| 字符 | 数量 | 处理 |
| --- | ---: | --- |
| 半角空格 `U+0020` | 51,720 | 保留（部分分隔型号/价格）或压缩连续空格 |
| 换行 `U+000A` | 11,939 | **转为句号或空格**，否则干扰分句与 tokenizer |
| `U+200C`（零宽不连字） | 31 | 删除 |
| `U+2028`（行分隔符） | 14 | 转普通换行或删除 |

**换行处理要小心**：数据里有 `虚假宣传行为\n1. 售前销售` 这种“标题 + 分条”的结构，换行是有意义的。建议**换行统一替换为句号** `。`（而不是直接删除），保留断句边界：

```python
text = re.sub(r"[\n\r\u2028]+", "。", text)
text = re.sub(r"[\u200c\u200b\ufeff]", "", text)   # 零宽字符
```

首尾空白样本数为 0，说明数据已做过 `strip`，这点不用管。

## 九、推荐的预处理流水线

把上述结论串成一条顺序正确的 pipeline（**顺序很关键**）：

```python
import re

_TONE_WORDS = "啊呀吧呢吗嘛哦噢喔诶唉哎嗨哈嘿呵嘻嗯唔哟咦哇咯啦嘞唷"

_EMOJI_RE = re.compile(
    "[\U0001F000-\U0001FAFF\U0001F1E6-\U0001F1FF\U00002600-\U000027BF"
    "\U00002190-\U000021FF\U00002B00-\U00002BFF\U0000FE00-\U0000FE0F"
    "\U0000200D\U000020E3\U0000FFFC\U0000FFFD]+")

def preprocess(text: str, use_opencc: bool = False) -> str:
    # 1. 修复方向控制符污染（必须先做，否则后续正则会被错乱字序干扰）
    text = re.sub(r"\u202e(.*?)\u202c", lambda m: m.group(1)[::-1], text)
    text = text.replace("\u202e", "").replace("\u202c", "")

    # 2. 清零宽字符
    text = re.sub(r"[\u200c\u200b\ufeff]", "", text)

    # 3. 剔除 emoji 与非汉字型情绪符号（图片占位、表情、箭头、键帽修饰符）
    text = _EMOJI_RE.sub("", text)

    # 4. 换行 → 句号（保留断句语义）
    text = re.sub(r"[\n\r\u2028]+", "。", text)

    # 5. 省略号归一化：连续点 → 单省略号 …（必须早于半角转全角）
    text = re.sub(r"\.{2,}", "…", text)
    text = re.sub(r"…{2,}", "…", text)

    # 6. 半角标点转全角（必须早于标点压缩，否则半角 ! ? , 会漏压）
    #    注意：故意不含 - / ' —— 它们是型号/单位/拼音连接符，转全角会破坏语义
    text = text.translate(str.maketrans({
        ",": "，", ":": "：", ";": "；", "!": "！", "?": "？",
        "(": "（", ")": "）", '"': "”",
    }))

    # 7. 连续标点压缩（！！！→！）
    text = re.sub(r"([，。！？；：、…])\1{1,}", r"\1", text)

    # 8. 重复语气词压缩（啊啊啊→啊），仅限白名单
    text = re.sub(r"([" + _TONE_WORDS + r"])\1{1,}", r"\1", text)

    # 9. 连续星号压缩（保留脱敏信号，减少 [UNK]）
    text = re.sub(r"\*{2,}", "*", text)

    # 10. 压缩连续空格
    text = re.sub(r" {2,}", " ", text).strip()

    # 11.（可选）繁转简
    if use_opencc:
        from opencc import OpenCC
        text = OpenCC("t2s").convert(text)

    return text
```

### 顺序为什么重要

- **修复 RLO 必须最先**：否则错乱字序会让后面的正则匹配到错误位置。
- **emoji 剔除放在标点处理之前**：避免 `✅` `1️⃣` 等符号干扰标点/重复的判断。
- **省略号正则必须早于半角转全角**：若先把 `.` 转成 `。`，`...` 就变成 `。。。`，无法识别为省略号。
- **半角转全角必须早于标点压缩**：否则半角 `!!!`、`,,` 在压缩时（正则只认全角）会被漏掉，转全角后才暴露为重复标点。实测踩过这个坑——调整顺序后，残留的重复标点从 6 条降为 0。
- **星号压缩放在转全角前**：`*` 不受全角转换影响，但顺序上先处理更清晰。

| 全角拉丁字母 | 1 条样本 | 0（转半角） |
| 连续星号 | 32,420 个 | 压缩但保留 |
| 半角标点 | 约 6,000 个 | 转全角（`-` `/` 除外；`'` 剔除） |
| 繁体字 | 33 个 | 按需（默认可不处理） |

> 合计 **16,915 条样本**（56.38%）发生改变。

## 十一、一页纸总结

| 优先级 | 事项 | 做不做 | 理由 |
| --- | --- | --- | --- |
| P0 | 修复 `U+202E` 污染 | **必须** | 13 条真实污染，字序错乱 |
| P0 | 保留 `*` 打码 | **必须** | 是特征不是噪声，删了就丢信息 |
| P0 | 清除零宽字符 | **必须** | 非正常显示字符，应为 0 |
| P0 | 剔除 emoji / 图片占位符 | **必须** | 对分类无判别价值 |
| P1 | 标点统一转全角 | 建议 | 减少词表碎片，但排除 `-` `/` `'` || P1 | `...` → 单省略号 `…` | 建议 | 全库形态统一 |
| P1 | 换行 → 句号 | 建议 | 保留断句，便于分句与 tokenize |
| P1 | 重复标点 / 语气词压缩 | 建议 | 减少罕见 token，语气词限白名单 |
| P3 | 繁转简 | 可选 | 仅 33 个字，收益极低 |
| 不要做 | 删除所有标点 | **禁止** | 标点承载结构与断句信息 |
| 不要做 | 转 `-` `/` `'` | **禁止** | 它们是型号/单位/拼音连接符，转了破坏语义 |
| 不要做 | 无差别压缩重复汉字 | **禁止** | 会把拼多多→拼多、快团团→快团，破坏品牌词 |

> 一句话：非正常显示字符（`U+202E`、零宽字符）和 emoji 必须秒掉；标点统一转全角但要白名单式排除 `-` `/` `'`；省略号统一为单个 `…`；重复标点可压，重复语气词只在白名单内压（品牌名/拟声词的重复保留）；隐私打码星号保留。

## 十二、残余符号二次清查（本轮新增）

第一轮处理后，对输出做**逐字符残余扫描**，仍有若干低频异常符号。逐类确认后按“有意义则归一、无意义则剔除”处理：

| 符号 | 数量 | 判断 | 处理 |
| --- | ---: | --- | --- |
| `[` `]` | 183 / 169 | 仅出现在 `[ORDER_ID]` 隐私占位符 | **去括号**，保留其内内容 |
| `{` | 5 | 孤立笔误（`牢骚{行程`），无配对 | **剔除** |
| `Ⅰ` `Ⅱ` | 12 / 7 | 序号/型号（`抑菌液Ⅰ型`、`尼康Z7Ⅱ`） | **归一为 1 2** |
| `′` `″` `〞` | 5 / 3 / 6 | 误敲（`范围′内`、`一声″。`） | **剔除**（转引号会制造孤立引号，故直接删） |
| `'` `＇` | 18 / 1 | 拼音串误敲 / 误用引号 | **剔除** |
| `﹣`(U+FE63) | 12 | 小连字符，同 `-` | **归一为 `-`** |
| `–` `—` | 10 / 99 | 连接号 / 破折号 | **归一为 `-`** |
| `￥` | 4 | 全角人民币 | **归一为半角 `¥`** |
| `＃` | 4 | 全角井号 | **归一为 `#`** |
| `•` `◦` | 10 / 4 | 列表项目符号 | **归一为 `·`** |
| `∶` | 2 | 比例号误用冒号 | **归一为 `:`** |
| `Ｍ` `ｚ` | 1 / 1 | 全角拉丁字母（`Ｍｚ330`） | **归一为半角 `Mz330`** |
| `ヽ ´ Д ﾉ` `α` `｀` | 各 1~3 | 颜文字碎片 / 噪声字母 | **剔除** |

**刻意保留（有语义，不处理）**：`-` `/` `.`（型号、日期、金额、序号）、`%` `+` `*`（脱敏 `*`）、`@` `_` `|` `~` `\` `&` `=` `>`（链接、邮箱、公式）、`÷` `√` `≠`（算式）、`℃` `°`（单位）、`·` `●`（间隔与强调）、¥（金额）。

处理后再扫描，非常规字符从 66 种降至 40 种，且**剩余 40 种全部有合法语义**（全角中文标点 + 上列功能性符号）。

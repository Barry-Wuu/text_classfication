## 二、文本转张量策略

截断长度统一取 **`max_length=200`**（此前实测 P95≈201，>200 仅截极少数样本、几乎无损）。

### 方案 A：BERT tokenizer

用 `D:\models\bert-base-chinese`（词表 21128），逐字切分，转固定长度张量：

- `resources/tensors_bert.npz`：`input_ids` / `attention_mask` / `token_type_ids`（int32，`[30000,200]`）+ `labels`
- `resources/bert_token_lengths.npy`：截断前真实长度

实测：编码 30000 条约 4 秒；真实长度（含 CLS/SEP）P50=156、P95=184、P99=191、max=206，**超 200 被截断的仅 14 条**（0.05%）；npz 体积 5.1 MB。

脚本：`resources/to_tensor_bert.py`。

### 方案 B：jieba + 词频自训词表

jieba 分词 → 词频统计 → 构建词表（`<pad>=0`、`<unk>=1`，过滤纯标点，`min_freq>=2`）→ 整数序列 pad/truncate 到 200：

- `resources/vocab.txt`：一行一词，**行号即 id**
- `resources/tensors_tfidf.npz`：`text_ids [30000,200]` + `labels` + `lengths`
- `resources/tfidf_matrix.npz` / `tfidf_vectorizer.pkl`：TF-IDF 稀疏矩阵（对照）

实测：jieba 分词 30000 条约 19 秒；词表 28897；分词后序列长度 P50=93、P95=114、max=150（200 长度充裕，**截断 0 条**）；Top20 高频词为"我/的/了/在/月/不/年/平台/本人/元/日/9/客服/…"。脚本：`resources/to_tensor_tfidf.py`。

## 三、效果对比

### 3.1 一个必须说明的评估坑：增强泄漏

本数据集 77% 是规则增强样本，且**每条增强样本的 `id` 保留了其源样本 id**（形如 `源id#变体号`，`#` 前即源原始样本 id）。这带来一个隐蔽而严重的评估陷阱：

若对全量数据做**普通随机划分**，同一条原始投诉及其改写变体会被切到 train / test 两侧，测试集里大量样本在训练集里有"近亲"。此时模型不是在"学分类"，而是在"认同一句话的变体"，**任何随机划分的评估都会被系统性高估**。

项目在早期对比中确实踩过这个坑——某词袋模型在随机划分下拿到一个高得可疑的分数。后经按源 id 分组核查（`resources/leak_check.py`），确认随机划分下绝大多数测试样本的同源族都出现在训练集，存在实打实的泄漏，遂**弃用随机划分**、全面改用分组划分。此处仅作记录与警示，**不列出该虚高数值**，以免误导。

### 3.2 无泄漏重比：三条张量策略

评估协议：**按源 id 分组**——测试集 = 原始样本中按源切出的 20%，其全部增强变体排除出训练；训练集 = 其余原始样本 + 非测试源的增强样本；**测试只用原始样本**。

实测环境：Kaggle 云端 GPU（torch 2.10+cu128），数据从 GitHub `Barry` 分支拉取 `train_augmented.csv`。脚本：`resources/compare_no_leak.py`。

| 策略 | macro-F1 | 准确率 | 训练耗时 | 说明 |
|---|---:|---:|---:|---|
| **A. BERT 微调** | **0.8371** | 0.8396 | 885s（GPU） | bert-base-chinese，2 epoch |
| B. TF-IDF + LinearSVC | 0.8221 | 0.8229 | 13.2s（CPU） | 词表 25251 |
| C. 词频随机嵌入 | 0.4742 | 0.5131 | 31.7s（CPU） | 无监督随机嵌入 |

### 3.3 TF-IDF 之上换分类器：多算法横向对比

同一份 TF-IDF 特征（jieba 分词 + 词频，`min_df=2`，25,251 维）+ 同一无泄漏划分，横向比 12 个方法（fastText 用同一训练/测试集自行分词；Jev 直接对测试文本调大模型 API）。脚本：`resources/compare_tfidf_clf.py`、`resources/compare_tfidf_gbdt.py`、`resources/compare_fasttext.py`、`resources/compare_jev.py`（本机 CPU；Jev 走网络 API）。

| 方法 | macro-F1 | 准确率 | 耗时 |
|---|---:|---:|---:|
| LinearSVC | **0.8221** | 0.8229 | 7.3s（训练） |
| SGD（hinge） | 0.8138 | 0.8157 | 1.5s（训练） |
| ComplementNB | 0.8068 | 0.8128 | 0.1s（训练） |
| LogisticRegression | 0.7866 | 0.8012 | 11.1s（训练） |
| fastText | 0.7687 | 0.7779 | 36.1s（训练） |
| LightGBM | 0.7665 | 0.7845 | 377s（训练） |
| ExtraTrees | 0.7651 | 0.7729 | 787s（训练） |
| XGBoost | 0.7478 | 0.7649 | 1426s（训练） |
| MultinomialNB | 0.7455 | 0.7779 | 0.1s（训练） |
| RandomForest | 0.7351 | 0.7518 | 226s（训练） |
| Jev（大模型 API） | 0.7327 | 0.7351 | 85.7s（1378 条推理总耗时） |
| kNN（cosine） | 0.6364 | 0.6531 | 0.4s（训练） |

结论：

- **线性模型明显优于树模型**。TF-IDF 是 25,251 维的高维稀疏特征，线性模型天然契合；树模型在稀疏高维上难以有效分裂，RandomForest 训练 226 秒反而只有 0.7351，ExtraTrees 训练 787 秒也仅 0.7651。
- **梯度提升树同样不划算**（XGBoost / LightGBM）：作为"更强的树模型"，二者精度仅 0.75～0.77，仍落后线性模型 5～7 个点；XGBoost 训练要 1,426 秒（约 LinearSVC 的 200 倍），LightGBM 因直方图算法 + 叶子生长更快（377 秒）但仍不敌线性 SVM。
- **fastText 表现中游**（0.7687）：36 秒训练，优于全部树模型，但比线性 SVM 低约 5 个点。原因在于本文本的关键信号集中在少数强判别词（品牌/业务词），词袋线性模型已能充分捕捉，fastText 的 n-gram 子词与浅层嵌入未带来额外收益。
- **大模型 API 未占优**（Jev 0.7327）：Jev 是 TypeSafe 的 System One 模型，用 Choice 原语把 18 个类名作为候选项做结构化分类，返回判定与置信度（平均置信 0.914），无需训练数据。但全量 1378 条上仅 0.7327，低于线性 SVM 约 9 个点、略高于随机森林；优势在于零训练、开箱即用，而非精度。
- **朴素贝叶斯是秒级兜底**：ComplementNB 仅 0.1 秒即得 0.8068。

### 3.4 结论与部署推荐

1. **真实泛化水平约 0.82**；此前随机划分下的虚高分数属泄漏所致，对外一律以本节数字为准。
2. 部署推荐——**TF-IDF + 线性 SVM**：精度最高（0.8221），训练秒级、推理毫秒级、模型几 MB、零框架依赖。
3. **换其它分类器并不更优**：无论随机森林、ExtraTrees，还是更强的梯度提升树 XGBoost / LightGBM，都更慢更差，朴素贝叶斯更快但略低——LinearSVC 仍是精度与速度的最佳平衡点。
4. **BERT 微调精度最高但代价高昂**：早期 2 epoch 初步微调为 0.8371；后续按抽样协议（每轮随机抽 1024 条）续训至 105 轮后，前 100 轮最优（epoch 59）达 **macro-F1 0.8660 / 准确率 0.8628**，成为全榜第一，比 TF-IDF + SVM 高约 4.4 个点，但需 GPU 与约 1,292 秒训练。此前"差距有限"的判断源于把 BERT 当**冻结特征提取器**（抽 `[CLS]` 向量再喂 SVM）而非真正微调。
5. 词频随机嵌入最差（**0.4742**）：随机初始化嵌入无预训练知识、均值池化又抹平词序，泄漏一撤即原形毕露。
6. **暴露出的数据问题**：本数据集因增强变体共享领域词，**任何随机划分的评估都会被系统性高估**；后续所有报告指标都必须采用**按源 id 分组**的划分。

补充（打榜视角）：把上述方法画到"耗时（横轴，对数）—macro-F1（纵轴）"平面上，帕累托最优边界共 4 个成员——**ComplementNB**、**SGD**（hinge 损失）、**LinearSVC** 凭速度与精度兼顾占据左上角，**BERT 微调**以最高 macro-F1（0.8660）占据最右端；树模型与大模型 API 全部落在边界之内（被支配区），两个专家组集成同样被支配。图见 `resources/figures/10_pareto.png`。即在本任务上"快"与"准"各有一条路径：要性价比选 ComplementNB / LinearSVC，要绝对精度选 BERT。

### 3.5 传统老机器学习"专家组"集成实验

把 6 个**非树**传统模型（LinearSVC / SGD(hinge) / LogisticRegression / ComplementNB / MultinomialNB / kNN，按需求剔除 4 个树模型）当作 6 位"专家"，在同一份 TF-IDF 上独立训练后做硬投票 / 软投票（SVM 类无 `predict_proba`，用 OvR `decision_function` 经 softmax 近似成概率）。脚本：`resources/compare_ensemble.py`。

| 集成方式 | macro-F1 | 准确率 |
|---|---:|---:|
| 硬投票 HardVoting | 0.8048 | 0.8099 |
| 软投票 SoftVoting | 0.7843 | 0.7954 |
| oracle（任一专家对，理论上限） | — | 0.9028 |
| 专家分歧率 | — | 0.3824（527/1378） |

结论：**朴素集成未反超单模型最优**——硬投票 0.8048 / 软投票 0.7843 均低于 LinearSVC（0.8221）。原因：6 位专家高度同质（都吃同一份 TF-IDF、假设空间都偏线性），多数票只是把最强者拉向中庸；oracle 上限 0.9028 说明互补空间真实存在，但需更聪明的仲裁（stacking / 按置信度加权 / 只挑互补子集）而非简单多数才能兑现。分歧率 0.3824 是理论上能发力的区间，但本任务强判别词信号集中、线性模型已近饱和，提升有限。

### 3.6 BERT 微调与两张经典曲线

BERT（`bert-base-chinese`）在 Kaggle GPU 上按抽样协议微调：每个 epoch 只从训练集随机抽 1,024 条（不整份），每轮记录 用时 / 训练损失 / 训练集准确率 / 测试集准确率 / macro-F1 并保存权重；测试准确率相对最佳下降 ≥0.03 即停。实际在第 105 轮触发停止。脚本：`resources/compare_bert_finetune.py` 与 `resources/continue_bert{,2,3}/`。

| 图 | 文件 | 看点 |
| --- | --- | --- |
| 训练损失曲线 | `resources/figures/11_bert_loss.png` | 损失 2.64 快速跌至 0.5 以内（前 8 轮），20 轮后贴地并于 0.01～0.07 抖动——预训练表征已含任务知识，后期降损不再换来泛化 |
| 训练/测试准确率 | `resources/figures/12_bert_acc.png` | 训练准确率爬到 98.1%、后 40 轮贴 99%～100%；测试准确率第 30 轮后停在 84%～86% 平台，末轮张口 15.1 个点。抽样带来的随机梯度噪声把过拟合推后，是"抽样而非整份训练"的价值 |

前 100 轮中测试准确率最高为 **epoch 59（0.8628 / macro-F1 0.8660）**，其权重 `bert_epoch59.pt` 已作为打榜模型（若按 macro-F1 选，最优是 epoch 86 的 0.8685，但该轮权重已被滚动保存策略删除）。逐轮曲线与选模依据见 GitHub Release `bert-weights` 附件 `bert_best100.json`。

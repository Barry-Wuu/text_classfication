## 二、文本转张量策略

截断长度统一取 **`max_length=200`**（此前实测 P95≈201，>200 仅截极少数样本、几乎无损）。

### 方案 A：BERT tokenizer

用 `D:\models\bert-base-chinese`（词表 21128），逐字切分，转固定长度张量：

- `resources/tensors_bert.npz`：`input_ids` / `attention_mask` / `token_type_ids`（int32，`[30000,200]`）+ `labels`
- `resources/bert_token_lengths.npy`：截断前真实长度

实测：编码 30000 条约 4 秒；真实长度（含 CLS/SEP）P50=156、P95=184、P99=191、max=206，**超 200 被截断的仅 14 条**（0.05%）；npz 体积 5.1 MB。

脚本：`resources/to_tensor_bert.py`。

### 方案 B：jieba + 词频自训词表

jieba 分词 → 词频统计 → 构建词表（`<pad>=0`、`<unk>=1`，过滤纯标点，`min_freq>=2`）→ 整数序列 pad/truncate 到 200：

- `resources/vocab.txt`：一行一词，**行号即 id**
- `resources/tensors_tfidf.npz`：`text_ids [30000,200]` + `labels` + `lengths`
- `resources/tfidf_matrix.npz` / `tfidf_vectorizer.pkl`：TF-IDF 稀疏矩阵（对照）

实测：jieba 分词 30000 条约 19 秒；词表 28897；分词后序列长度 P50=93、P95=114、max=150（200 长度充裕，**截断 0 条**）；Top20 高频词为"我/的/了/在/月/不/年/平台/本人/元/日/9/客服/…"。脚本：`resources/to_tensor_tfidf.py`。

## 三、效果对比

### 3.1 一个必须说明的评估坑：增强泄漏

本数据集 77% 是规则增强样本，且**每条增强样本的 `id` 保留了其源样本 id**（形如 `源id#变体号`，`#` 前即源原始样本 id）。这带来一个隐蔽而严重的评估陷阱：

若对全量数据做**普通随机划分**，同一条原始投诉及其改写变体会被切到 train / test 两侧，测试集里大量样本在训练集里有"近亲"。此时模型不是在"学分类"，而是在"认同一句话的变体"，**任何随机划分的评估都会被系统性高估**。

项目在早期对比中确实踩过这个坑——某词袋模型在随机划分下拿到一个高得可疑的分数。后经按源 id 分组核查（`resources/leak_check.py`），确认随机划分下绝大多数测试样本的同源族都出现在训练集，存在实打实的泄漏，遂**弃用随机划分**、全面改用分组划分。此处仅作记录与警示，**不列出该虚高数值**，以免误导。

### 3.2 无泄漏重比：三条张量策略

评估协议：**按源 id 分组**——测试集 = 原始样本中按源切出的 20%，其全部增强变体排除出训练；训练集 = 其余原始样本 + 非测试源的增强样本；**测试只用原始样本**。

实测环境：Kaggle 云端 GPU（torch 2.10+cu128），数据从 GitHub `Barry` 分支拉取 `train_augmented.csv`。脚本：`resources/compare_no_leak.py`。

| 策略 | macro-F1 | 准确率 | 训练耗时 | 说明 |
|---|---:|---:|---:|---|
| **A. BERT 微调** | **0.8371** | 0.8396 | 885s（GPU） | bert-base-chinese，2 epoch |
| B. TF-IDF + LinearSVC | 0.8221 | 0.8229 | 13.2s（CPU） | 词表 25251 |
| C. 词频随机嵌入 | 0.4742 | 0.5131 | 31.7s（CPU） | 无监督随机嵌入 |

### 3.3 TF-IDF 之上换分类器：多算法横向对比

同一份 TF-IDF 特征（jieba 分词 + 词频，`min_df=2`，25,251 维）+ 同一无泄漏划分，横向比 8 个分类器。脚本：`resources/compare_tfidf_clf.py`（本机 CPU）。

| 模型 | macro-F1 | 准确率 | 训练耗时 |
|---|---:|---:|---:|
| LinearSVC | **0.8221** | 0.8229 | 7.3s |
| SGD（hinge） | 0.8138 | 0.8157 | 1.5s |
| ComplementNB | 0.8068 | 0.8128 | 0.1s |
| LogisticRegression | 0.7866 | 0.8012 | 11.1s |
| ExtraTrees | 0.7651 | 0.7729 | 787s |
| MultinomialNB | 0.7455 | 0.7779 | 0.1s |
| RandomForest | 0.7351 | 0.7518 | 226s |
| kNN（cosine） | 0.6364 | 0.6531 | 0.4s |

结论：

- **线性模型明显优于树模型**。TF-IDF 是 25,251 维的高维稀疏特征，线性模型天然契合；树模型在稀疏高维上难以有效分裂，RandomForest 训练 226 秒反而只有 0.7351，ExtraTrees 训练 787 秒也仅 0.7651。
- **随机森林并不划算**：精度比 LinearSVC 低约 9 个点，训练慢 30 倍以上。
- **朴素贝叶斯是秒级兜底**：ComplementNB 仅 0.1 秒即得 0.8068。

### 3.4 结论与部署推荐

1. **真实泛化水平约 0.82**；此前随机划分下的虚高分数属泄漏所致，对外一律以本节数字为准。
2. 部署推荐——**TF-IDF + 线性 SVM**：精度最高（0.8221），训练秒级、推理毫秒级、模型几 MB、零框架依赖。
3. **换其它分类器并不更优**：随机森林/ExtraTrees 更慢更差，朴素贝叶斯更快但略低，LinearSVC 仍是精度与速度的最佳平衡点。
4. **BERT 微调略优但代价高昂**：比 TF-IDF + SVM 高约 1~1.5 个百分点（0.8371），却需 GPU 与数十倍训练时间；仅当机器需理解未见语义改写、且能承担 GPU 成本时才值得上。
5. 词频随机嵌入最差（**0.4742**）：随机初始化嵌入无预训练知识、均值池化又抹平词序，泄漏一撤即原形毕露。
6. **暴露出的数据问题**：本数据集因增强变体共享领域词，**任何随机划分的评估都会被系统性高估**；后续所有报告指标都必须采用**按源 id 分组**的划分。

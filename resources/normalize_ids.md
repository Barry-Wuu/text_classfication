# 强标识符省流说明

本文记录 `resources/normalize_ids.py` 的设计，以及它相对 `clean.csv` 做了什么。

## 一、为什么只省流"手机号 / 信用代码 / 订单号"

字符级清洗（`preprocess.py`）之后，数据里仍残留大量**强标识符**：手机号、统一社会信用代码、订单号 / 运单号 / 流水号等。它们有三个共同点：

1. **每条各不相同** —— 是随机串，不是可学习的模式；
2. **零判别力** —— 分类看的是"投诉什么事"，不是"订单号是多少"；
3. **污染词表** —— 作为 token 几乎不重复，只会撑大词表、制造罕见 token。

因此把它们的**内容**省流为占位符，只保留"这里有一个什么类型的标识符"这一信息。

### 上游脱敏并不彻底

数据集上游只做了**部分脱敏**：保留了前缀、遮掉中间，例如

```
订单号：42000*091*            （原为完整长订单号）
手机号：17888*46508
统一社会信用代码：914*MA5FJKYQ7L
```

这些"前缀 + 星号"的残留串仍是噪声。本脚本把**整段**（前缀 + 星号 + 后缀）替换为占位符。

## 二、占位符设计

| 占位符 | 对应实体 | 识别方式 |
| --- | --- | --- |
| `<手机号>` | 手机号 / 电话 | 引导词：手机号、手机号码、联系电话、电话号码、联系方式、电话 |
| `<信用代码>` | 统一社会信用代码 | 引导词：统一社会信用代码、社会信用代码、信用代码、纳税人识别号、营业执照号 |
| `<车架号>` | 车架号 / VIN | 引导词：车架号、车架号码、VIN |
| `<订单号>` | 订单 / 运单 / 流水 / 工单 / 序列号 | 引导词：订单号、单号、运单号、快递单号、流水号、工单号、序列号、交易单号、处罚单号、编号 等 |
| `<ID>` | 无引导词、但明显是脱敏串 / 长数字 | 含星号的裸脱敏串、或 6 位以上纯数字串 |

**标识符本体的判定**（避免误伤产品型号）：

- 必须以**数字开头**，或**串中含星号**；
- 纯字母串（如 `WiFi`）不算标识符 —— 这样 `小米折叠手机mixflip2` 不会被误伤。

## 三、刻意不处理的内容

| 内容 | 例子 | 原因 |
| --- | --- | --- |
| 金额 | `16999元` | 数量级跨类别有判别力（通讯中位 35 元 vs 教育 3099 元） |
| 日期 | `2026年9月2日` | "有无日期"的结构有判别力（各分类占比 39%~71%） |
| 数量/次数/天数 | `12天`、`2位男士` | 是语义量词，是内容不是噪声 |
| 产品型号 | `iPhone17`、`mate70pro` | 是内容 |
| 人名打码 | `夏*医生`、`高*` | 隐私保护，且为单字无法进一步处理 |
| 算式中的星号 | `29*25=725` | `*` 是乘号，有语义 |
| markdown 格式符 | `*一、事情经过*` | 原数据格式残留 |

## 四、处理结果

| 项目 | 处理前 | 处理后 |
| --- | --- | --- |
| 含引导词 + 标识符 | 2,053 条 | 0 |
| 含裸脱敏串（`*`） | 2,982 条 | 0 |
| ORDER_ID 占位符 | 54 处 | 0（归入 `<订单号>`） |
| 残留星号样本 | 3,052 条 | 94 条（全部为非标识符：人名/算式/格式） |

**发生变化的样本：3,014 条（10.05%）。**

各占位符命中样本数：`<订单号>` 1,766、`<ID>` 1,241、`<手机号>` 312、`<信用代码>` 36、`<车架号>` 32。

## 五、产物与用法

```
python resources/normalize_ids.py            # 只统计，不落盘
python resources/normalize_ids.py --write    # 生成 clean_ids.csv（项目根目录）
```

- **`clean.csv`** —— 保守版：仅字符级清洗，标识符保留原样（含脱敏残留）。
- **`clean_ids.csv`** —— 本版：在 `clean.csv` 基础上进一步省流强标识符。

建议**两版各训一次**，用真实准确率验证"省流标识符"是否带来增益，而不是凭直觉取舍。
